# Do marketing guardrail Skills actually catch anything Claude wouldn't?

An eval of three ways to check marketing copy with Claude before it's published: plain Claude, a set of free guardrail Skills, and the Guardrails for Marketing Teams pack. Built and run in November 2026 on Claude Sonnet 5.5.

> **Provisional.** Every number below comes from a single run per draft at default temperature. A rerun with three repeats per draft, plus a fourth setup (see "The length control"), is set up in `rerun.sh` and hasn't landed yet. Treat small differences as noise until it does.

**Short answer:** on catching planted problems, the three setups can't be told apart. Plain Claude caught 99 of 102, the free Skills 98, the Guardrails pack 102, and a paired test between plain Claude and Guardrails gives p = 0.25. Plain Claude made the best publish calls (183 of 192 right) and raised the fewest false alarms. If Guardrails adds anything, it's consistency and the last few subtle style and placement problems, and it costs about 50% more per draft to run.

## What was tested

**The drafts.** A fictional UK tea brand, Pebblebrook Tea Co., with a written brand policy (claims it can prove, words it never uses, how it labels ads). 24 clean drafts across landing pages, emails, search ads, product pages, creator posts and an affiliate review, using only claims the policy allows. Then variants with problems planted at exact, known positions:
- **Round 1, obvious (29 problems):** "The UK's best loose leaf tea", "Loved by 50,000 tea drinkers", "boosts your immunity", "carbon neutral", "only 40 tins are left", "In today's fast-paced world", a creator post with its "Ad" label removed.
- **Round 2, subtle (22 problems):** the review count quietly changed from 1,200 to 2,000; "noticeably smoother than supermarket tea bags"; "help you wind down and sleep better"; "packed with antioxidants"; "planet-friendly packaging"; "while stocks last"; "#ad" buried in the middle of seven hashtags; an affiliate link disclosed only in a footnote; "Brewed with care. Packed with love. Delivered with a smile."; "Was £12, now £8" with no price history.

**The setups**, each given the same task and the same policy:
1. **Plain Claude:** "You are a careful marketing editor. Check marketing copy before it is published."
2. **Free Skills:** Claims Guard, Slop Guard and Honest Review Rules from the free, CC BY marketing Skills.
3. **Guardrails pack:** the publish gate plus its claims, regulated claims, disclosure and house style checks. It's a free download from marketingprompthub.com/guardrails/.

**Two policy levels.** Every round ran twice: once with the full brand policy (which spells out banned phrases), and once with a bare one (who the brand is and the claims it can prove, nothing more). Most real teams have something closer to the bare one. So the 102 problems are 51 planted problems, each tested at both policy levels.

**How it ran.** Each draft went to Claude headless with no tools, no settings and no memory (`claude -p`), and the reply had to end with a JSON list of problems, quoting the draft's exact words, plus a publish or don't-publish decision. 576 runs in all.

**How it was scored.** All the rules are in `score.py` and covered by tests.
- A planted problem counts as caught when a flagged quote matches it word for word: either the quote contains the whole problem, or it's a long enough piece of it (at least two meaningful words, or 40% of the problem's words) that sits inside it or shares 60% of its words. A one-word quote like "tea" or "ad" doesn't count.
- A missing label counts as caught only when a missing disclosure flag points at it: it quotes the draft's opening words (which the task asks for) or mentions the ad, gift, affiliate link or disclosure.
- If two flags hit the same planted problem, the second is counted as a duplicate, not hidden and not a false alarm.
- Every other flag was ruled by hand as **valid** (a real problem my test set had missed), a **false alarm**, or **borderline**, with a reason for each, in `data/adjudication.json`.

I tightened the scoring after a review pointed out the first version could count a one-word quote as a catch. Rescoring the same runs with the stricter rules changed no catches, so the headline numbers stand.

## Results (provisional, single run)

Generated by `python3 score.py summary`, which writes `results/summary.md`.

| Plain Claude | 29/29 | 29/29 | 21/22 | 20/22 | **99/102** |
| Free Skills | 29/29 | 28/29 | 20/22 | 21/22 | **98/102** |
| Guardrails pack | 29/29 | 29/29 | 22/22 | 22/22 | **102/102** |

**Publish calls and false alarms** (all four runs added together)

| | Publish call right | Clean drafts blocked | Duplicate flags on a planted problem | Real problems my test set missed | False alarms | Borderline | Cost per 50 drafts | Seconds per draft |
|---|---|---|---|---|---|---|---|---|
| Plain Claude | 183/192 (95%) | 6/96 (6%) | 7 | 13 | 1 | 1 | $0.46 | 10 |

A clean draft is one with nothing planted. Every clean draft that got a flag was also blocked, so "clean drafts blocked" is the same as "clean drafts flagged" here.

**Are the differences real?** Exact McNemar tests on the same 102 problems and 192 publish calls. "A only" is how many A got right that B didn't.

| | Problems: A only, B only, p | Publish calls: A only, B only, p |
|---|---|---|
| Plain Claude vs Free Skills | 3, 2, p = 1.00 | 12, 2, p = 0.01 |
| Plain Claude vs Guardrails pack | 0, 3, p = 0.25 | 6, 4, p = 0.75 |
| Free Skills vs Guardrails pack | 0, 4, p = 0.12 | 3, 11, p = 0.06 |

The p values on problems are if anything too generous to Guardrails: plain Claude's three misses include the same "Brewed with care" triplet at both policy levels, so one weakness counts twice.

## What it means

- **On catching problems, it's a tie.** Plain Claude and Guardrails disagreed on 3 of 102 problems. That's too few to separate them, and the same pattern could easily come from chance.
- **Plain Claude made the best publish calls.** It got 183 of 192 right, blocked the fewest clean drafts (6 of 96) and raised one false alarm in four runs. The free Skills were clearly worse at this (p = 0.01): they blocked 15 clean drafts.
- **The obvious stuff is solved.** With or without a policy, every setup caught nearly every blatant problem in round 1. If your worry is "Claude will let 'clinically proven' through", it mostly won't.
- **Where Guardrails might help is the subtle style and placement items.** Plain Claude's three misses were the tidy "Brewed with care. Packed with love. Delivered with a smile." triplet (twice) and an affiliate link disclosed only in a footnote. Guardrails caught those. Whether it does so reliably, or just got lucky once, is what the repeats will show.
- **It costs more to run.** Guardrails used about 50% more per draft than plain Claude ($0.68 against $0.46 per 50 drafts) and raised 8 false alarms to plain Claude's 1.
- **The free Skills over-flag.** They raised the most false alarms, mostly by questioning claims the policy allows and by asking for disclosure where it was already given. That's the first thing to fix in them.
- **The written policy mattered less than I expected.** Results with the full and bare policy were within a point or two of each other.

## The length control

The plain Claude prompt is one line, and both Skill setups add thousands of words. So a fair question is whether the Skills help just because they make the prompt longer and more specific. The rerun adds a fourth setup, `baseline_long`: plain Claude plus a generic marketing review checklist (`data/generic-review-checklist.md`) of about the same length as the Guardrails text (11,169 characters against 10,694). It's written from general advertising review common sense: claims need evidence, no health claims, label ads and affiliate links, no fake urgency, avoid AI clichés. It doesn't use the Guardrails text, and a test checks it shares no three-word phrase with any planted problem, so it isn't being taught the answers either.

## What I'd change next

1. **Land the three-repeat rerun** with the length control, and update every number here from `results/summary.md`.
2. **Make round 3 harder still,** with problems that need context, such as a claim that's true for one product but not another, or a disclosure that's present but not prominent enough on mobile. Write it before looking at any Skill text.
3. **Cut the free Skills' false alarms** by teaching them to check the policy's approved claims before flagging, then rerun.
4. **Test another model.** Everything here is Claude Sonnet 5.5; a smaller model might show bigger gaps between the setups.

## Limits, honestly

- I wrote the drafts, the planted problems and the rulings, and I also wrote the Skills being tested, both the free ones and Guardrails. The rulings and their reasons are all in the repo so you can disagree with them. Guardrails is now free, so I've no commercial interest in it winning, but I'd still rather it did, so read my rulings with that in mind.
- The round 2 cases were written after the Skills, by the person who wrote the Skills. That's a real risk of designing problems the Skills were already built to catch, which would flatter both Skill setups.
- The plain Claude prompt is a one-liner, so any gap between it and the Skills could just be about length and detail. That's why the rerun adds `baseline_long`.
- Every draft ran once per setup at default temperature, so a difference of one or two problems could be noise. The rerun repeats each draft three times.
- One fictional brand, UK English, one model.
- The 102 problems are 51 problems at two policy levels, so they aren't 102 independent tests.
- Asking for a JSON list of problems changes how the model answers a little. All setups had the same instruction.

## Run it yourself

```
python3 data/build_cases.py && python3 data/build_cases_v2.py
POLICY=minimal python3 run.py v1-min                          # round 1, bare policy
CASES=cases-v2.json POLICY=full python3 run.py v2-full        # round 2, full policy
REPEATS=3 CASES=cases-v2.json python3 run.py v2-full baseline # three repeats of one setup
python3 score.py v2-full --flags                              # one run, with every unmatched flag
python3 score.py summary                                      # all runs in one table, writes results/
./rerun.sh 2>&1 | tee rerun.log                               # the full three-repeat rerun
```

Needs the Claude CLI signed in. Download the Guardrails pack from marketingprompthub.com/guardrails/ and set `GUARDRAILS_SKILLS` to its unzipped skills folder (`PAID_SKILLS` still works as the old name). The free Skills are at github.com/zaraonrecord/claude-marketing-skills.

Each result stores a hash of the prompt, model and policy, and is reused only when that matches, so changing a Skill or the policy can't quietly mix old and new results. Each run also writes `runs/<version>/manifest.json`, which `score.py` reads to know which cases it used.

Tests: `uvx ruff check . && uv run --no-project --with pytest python -m pytest -q`
